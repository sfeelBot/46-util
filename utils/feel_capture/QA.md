## 2026-07-23 — (개발 중 자체 발견) 스모크 테스트에서 녹화 완료 시그널이 수신되지 않는 것처럼 보임

- **증상**: `RecorderThread`를 실제로 `.start()`시켜 gif 녹화 후 `.wait()`로 스레드 종료를 기다렸는데, 연결해둔 `finished_result` 콜백이 호출되지 않은 것처럼 보임(`results` 딕셔너리가 비어 있음).
- **원인**: 코드 버그가 아니라 테스트 스크립트의 문제였음. `RecorderThread`(QThread)가 별도 OS 스레드에서 `finished_result.emit(...)`을 호출하면 Qt가 이를 메인 스레드의 이벤트 큐에 넣는 큐드 커넥션으로 처리하는데, 테스트 스크립트가 `QApplication.exec_()`나 `processEvents()`를 호출하지 않아 큐에 쌓인 시그널이 실제로 전달되지 않았던 것. 실제 앱(`main.py`)은 `app.exec_()`로 이벤트 루프가 항상 돌고 있으므로 이 문제와 무관함.
- **해결**: 테스트 스크립트에 `app.processEvents()` 호출을 추가해 큐에 쌓인 시그널을 처리하도록 수정 → gif(2901 bytes)/mp4(5089 bytes) 파일이 실제로 정상 생성되고 `finished_result`가 `(True, "저장됨: ...")`로 정확히 전달됨을 확인.
- **비고**: 별도의 순수 `threading.Thread`로 `RecorderThread.run()`을 직접 호출해본 결과, 이벤트 루프 유무와 무관하게 실제 녹화(파일 쓰기)는 항상 정상 동작함을 재확인함 — 즉 문제는 "시그널 전달 확인 방법"에만 있었고 녹화 로직 자체는 처음부터 정상이었음.

## 2026-07-23 — (서브에이전트 독립 검증에서 발견) `overlay_region.RegionBox` 리사이즈 시 서/북 핸들을 반대쪽 경계 너머로 드래그하면 박스가 순간이동함

- **증상**: 영역 박스의 서(w)/북(n)/북서(nw) 리사이즈 핸들을 마우스로 반대쪽 경계보다 더 멀리(빠르게) 드래그하면, 박스가 그 자리에서 최소 크기로 자연스럽게 멈추는 게 아니라 **커서 위치로 통째로 순간이동(teleport)하면서 반대쪽(원래 고정되어 있어야 할) 경계 위치를 완전히 잃어버린다.**
  - 재현(코드 레벨, `overlay_region.RegionBox` 단위 테스트로 확인): 화면 좌표 `x=100,y=100,w=200,h=150`(우측 경계 x=300)인 박스에서 서쪽 경계를 잡고 커서를 `x=500`까지 오른쪽으로 드래그하면, 결과 geometry가 `x=498, width=30`이 된다. 즉 원래 오른쪽 경계(300)는 완전히 사라지고, 박스가 커서 바로 아래에 30px짜리 상자로 다시 생성된 것처럼 보인다.
  - 반대로 동(e)/남(s)/남동(se) 핸들을 반대쪽 경계 너머로 드래그하는 경우는 이 문제가 없다 — 원래 고정된 좌측/상단 모서리에 정상적으로 앵커링된 채 최소 크기(30px)로 클램프된다(예: se 핸들을 nw 모서리 너머로 드래그 → `x=100,y=100,w=30,h=30`으로 정상적으로 원래 좌상단에 앵커됨).
- **원인**: `overlay_region.py`의 `mouseMoveEvent`에서 리사이즈 시 `geom.setLeft()`/`setTop()`(서/북 핸들)로 좌측·상단 좌표를 직접 이동시키는데, 이때 반대쪽(우측/하단) 좌표는 `self._drag_start_geom`의 원래 값 그대로 둔다. 드래그가 반대쪽 경계를 넘어서면 `width()`/`height()`가 음수가 되고, 그 다음 클램프 코드(`if geom.width() < MIN_SIZE: geom.setWidth(MIN_SIZE)`)가 실행된다. `QRect.setWidth()`는 `x()`(좌측 좌표)는 그대로 두고 우측 좌표만 재계산하는데, 서/북 핸들의 경우 바로 그 `x()`/`y()`가 **방금 드래그로 움직인(그래서 반대쪽 경계를 이미 넘어버린) 값**이라서, 클램프가 "원래 고정되어 있어야 할 반대쪽 경계"가 아니라 "방금 넘어간 커서 위치"를 앵커로 삼아버린다. 동/남/se 핸들은 애초에 `x()`/`y()`(좌측/상단)를 건드리지 않으므로 이 문제가 발생하지 않는다 — 즉 버그는 서/북 계열 핸들(w, n, nw, 그리고 ne/sw는 각각 한 축만)에 국한된 비대칭 문제다.
- **해결 (2026-07-23)**: `mouseMoveEvent`를 서브에이전트가 제안한 방식 그대로 수정 — `setWidth()`/`setHeight()`로 사후 클램프하는 대신, w/e/n/s 각 핸들마다 "반대쪽(고정되어야 할) 경계"를 앵커로 두고 `min()`/`max()`로 새 좌표 자체를 `앵커 ± (MIN_SIZE - 1)` 이내로 미리 제한한 뒤 `setLeft()`/`setRight()`/`setTop()`/`setBottom()`을 호출하도록 변경. 재현 스크립트(`x=100,y=100,w=200,h=150` 박스의 서쪽 핸들을 x=500까지 드래그)로 재검증 → 결과가 `x=270,w=30`(오른쪽 경계 299 그대로 앵커됨)으로 정상화됨을 확인.
- **검증 방법**: 실제 마우스 조작이 아니라, `unittest.mock.Mock`으로 `QMouseEvent`를 흉내내어 `RegionBox.mousePressEvent`/`mouseMoveEvent`를 직접 호출하는 방식으로 재현(headless, `QT_QPA_PLATFORM=offscreen`). 실제 사람이 마우스로 빠르게 드래그했을 때 시각적으로 어떻게 보이는지(순간이동이 눈에 띄게 거슬리는 정도)는 이번 검증에서 실제 마우스 조작으로 확인하지 못했음 — 코드 레벨의 좌표 계산 버그만 확인함.

## 2026-07-23 — (서브에이전트 독립 검증에서 발견) `config.load_config()`가 `region_presets`이 빈 리스트인 config.json을 만나면 기본 프리셋 3개로 복구되지 않고 빈 리스트를 그대로 사용함

- **증상**: `%APPDATA%\FeelCapture\config.json`에 `"region_presets": []`가 들어있는 상태로 `load_config()`를 호출하면, 결과 `cfg["region_presets"]`가 (의도된 것으로 보이는) 기본 3개 프리셋으로 복구되지 않고 그대로 빈 리스트가 된다. 이 상태에서 영역 박스 우클릭 메뉴의 "프리셋 크기" 서브메뉴는 항목이 하나도 없는 빈 메뉴가 된다(크래시는 아니지만 사용자가 프리셋을 전혀 쓸 수 없게 됨).
- **원인**: `config.py`의 `load_config()`에서 `cfg.update(data)`가 먼저 실행되어 파일에 있는 `region_presets`(빈 리스트 포함) 값으로 `cfg`를 무조건 덮어쓴다. 그 다음에 있는 방어 코드
  ```python
  if "region_presets" in data and isinstance(data["region_presets"], list) and data["region_presets"]:
      cfg["region_presets"] = data["region_presets"]
  ```
  는 "`data["region_presets"]`가 falsy(빈 리스트)면 기본값으로 되돌린다"는 의도로 보이지만, 실제로는 이미 `cfg.update(data)`가 `cfg["region_presets"]`를 빈 리스트로 덮어쓴 뒤이므로, 이 `if`문의 조건이 거짓이 되어 그냥 통과할 뿐 아무것도 복구하지 않는다. 결과적으로 "빈 리스트면 기본값 유지"라는 의도와 반대로 빈 리스트가 그대로 남는다.
  (참고: `region_box`도 같은 `cfg.update(data)` → 부분 병합 패턴을 쓰지만, `region_box`는 항상 `{**DEFAULT_CONFIG["region_box"], **data["region_box"]}`로 병합하므로 이 문제가 없음을 별도로 확인함 — `region_presets`만 "덮어쓴 뒤 조건부로 되돌리려는" 방식이라 이 문제가 있음.)
- **영향 범위**: 실제 UI(`settings_dialog.SettingsDialog.result_config()`)는 프리셋 3칸을 항상 채워서 반환하므로(이름이 비어도 "프리셋N"으로 대체됨) 정상적인 앱 사용 흐름에서는 절대 빈 리스트가 저장되지 않는다. 즉 이 버그는 `config.json`을 수동으로 편집하거나 다른 도구로 잘못된 값을 넣었을 때만 발생하는 낮은 심각도의 엣지 케이스임.
- **해결 (2026-07-23)**: 서브에이전트가 제안한 방식 그대로 수정 — `cfg.update(data)` 이후 `if not cfg.get("region_presets"): cfg["region_presets"] = <기본값 3개>`로 무조건 사후 검사하도록 변경(빈 리스트/누락 모두 커버). `region_presets: []`만 담긴 config.json으로 재검증 → 기본 프리셋 3개(1920x1080/1280x720/800x600)로 정상 복구됨을 확인.
- **검증 방법**: 격리된 임시 `%APPDATA%` 경로에 `{"region_presets": []}`만 담긴 `config.json`을 직접 작성한 뒤 `load_config()` 호출 → 결과가 빈 리스트임을 확인(headless, 재현 스크립트로 검증).
