# filename_matching — processing.md

## 목적

이물검사 이미지 파일명을 "바코드 → 셀번호 → 재료명" 순으로 재가공하는 도구. GUI는 탭 2개로 구성된다.

- **탭 1 "바코드 → 재료명 변환"**: 원래 `barcode_to_cellNum.py`(바코드→셀번호) → `cellNum_to_barcode.py`(셀번호→재료명) 두 단계를 순서대로 따로 실행해야 했는데, 이 두 단계를 하나의 파이프라인으로 묶고 GUI로 미리보기/중복검사/일괄 변환/되돌리기까지 할 수 있게 만들었다.
- **탭 2 "Crop 이미지 재명명"**: 하나의 원본 이미지 안에 물리적으로 4개 셀이 찍혀 있어 `image_cropper` util로 4등분 crop한 경우, crop 순서(1~4)를 이용해 각 조각이 원래 개별 촬영이었다면 가졌을 저장번호 기반 파일명으로 되돌린다. 그 결과를 탭 1에 다시 입력하면 바코드→재료명 변환까지 이어갈 수 있다.
- **`gui_folder_remap.py` (별도 실행 GUI, "그룹폴더 기반 Crop 재명명")**: 탭 2와 비슷하지만, crop 파일명에 박힌 저장번호를 신뢰하지 않고 대신 **폴더 구조**(`{그룹번호}/cropped/`)로 각 crop이 어느 셀인지 판단한다. GitHub 이슈 #5 대응(파일명에 박힌 A열 저장번호가 실제 셀 위치와 어긋나는 문제).

## 사용법

```
.venv\Scripts\python.exe utils/filename_matching/gui.py
```

### 탭 1: 바코드 → 재료명 변환

1. **매핑 파일 확인/교체** — 시작 시 `mapping/barcode_cell_map.csv`, `mapping/cell_material_map.csv`, `mapping/storage_cellbarcode_map.csv`가 기본으로 로드됨. 다른 매핑표를 쓰려면 각 "매핑 불러오기..." 버튼으로 다른 CSV를 선택 (코드 수정 없이 교체 가능). 저장번호↔Cell Barcode 매핑은 구형 파일명만 처리하는 환경에서는 없어도 되며, 로드 실패해도 barcode/cell 매핑과 무관하게 앱은 계속 동작함(신형 파일명만 매칭 실패로 표시)
2. **폴더 선택** — 대상 폴더 선택 시 하위 폴더까지 재귀적으로 스캔해 존재하는 확장자 목록을 체크박스로 보여줌
3. **확장자 선택 후 "목록 불러오기"** — 선택한 확장자만 대상으로 목록을 만들고, 각 파일의 최종 변환명(`{재료명}_{셀번호}_{원본파일명}`)을 미리보기로 계산. 바코드/저장번호 패턴이 없거나 매핑표에 없는 파일은 "매칭실패" + 사유로 표시되고 자동으로 체크 해제됨
4. **중복검사** — 현재 선택된 출력 모드(평탄화/구조유지) 기준으로 최종 변환명이 겹치는 항목을 찾아 빨간색으로 표시
5. **목록 우클릭 → "파일탐색기에서 열기"** — 원본 파일 위치를 탐색기로 바로 열어줌
6. **테이블 조작** — 모든 컬럼은 드래그로 자유롭게 폭 조절 가능. 셀(들)을 드래그로 선택한 뒤 Ctrl+C 를 누르면 엑셀처럼 탭/줄바꿈으로 구분된 텍스트가 클립보드로 복사됨
7. **출력 폴더 선택 + 출력 모드 선택**
   - 단일 폴더에 평탄화: 하위폴더 구분 없이 출력 폴더 하나에 모든 결과 파일을 모음
   - 원본 하위폴더 구조 유지: 출력 폴더 아래에 원본과 동일한 하위폴더 구조를 그대로 재현
8. **모두 변환** — 체크되고 매칭에 성공한 파일은 원본을 그대로 둔 채(복사) 출력 폴더로 복사. **매칭실패 파일은 체크 여부와 무관하게 `{출력폴더}/error/`에 원본 파일명 그대로 함께 복사됨**(나중에 확인/재처리할 수 있도록). 실행 직전 목적지 경로 충돌(같은 이름 중복, 또는 출력 폴더에 이미 같은 이름 존재 — error 폴더 포함)을 재검사해서, 충돌이 있으면 아무 파일도 복사하지 않고 팝업으로 충돌 목록을 보여줌
9. **되돌리기**
   - "되돌리기 (방금 실행)": 직전 변환에서 생성된 결과 파일(정상 변환분 + error 폴더 복사분 모두)만 삭제 (원본은 항상 그대로)
   - "로그 불러와서 되돌리기...": 앱을 재시작했어도, 출력 폴더에 남은 `_conversion_log_YYYYMMDD_HHMMSS.json`을 선택하면 해당 실행분만 되돌릴 수 있음

### 탭 2: Crop 이미지 재명명

1. `image_cropper`로 4등분 crop한 이미지들이 있는 폴더(보통 `{원본폴더}/cropped/`)를 선택
2. "오름차순으로 번호 매기기" 체크박스 — 기본은 미체크(내림차순, 기존 동작). 체크하면 crop1~4의 시리얼 배정 방향이 반대로 바뀜 (아래 "Crop 재명명 규칙" 참고)
3. 확장자 선택 후 "목록 불러오기" — 각 crop 파일명에서 ROI번호(1~4)와 원본 저장번호를 읽어 재명명 결과를 미리보기로 계산. image_cropper 출력 형식이 아니거나 ROI번호가 1~4 밖이거나 저장번호 패턴이 없으면 "매칭실패"
4. 이후 흐름(중복검사/우클릭 탐색기/테이블 조작/출력 폴더·모드/모두 변환/되돌리기)은 탭 1과 동일

### gui_folder_remap.py: 그룹폴더 기반 Crop 재명명 (별도 실행)

```
.venv\Scripts\python.exe utils/filename_matching/gui_folder_remap.py
```

crop 파일명에 박힌 저장번호를 신뢰할 수 없을 때(GitHub 이슈 #5) 쓰는 도구. 사용법은 탭 2와 거의 같지만:

1. 대상 폴더는 `{그룹번호}/cropped/{crop파일}` 구조여야 함 (예: `A1_매칭(4셀 이미지)/02/cropped/...`). 상위에 A1_매칭/A2_매칭 같은 분류 폴더가 몇 겹 있어도 상관없음 — 재귀 스캔 시 각 파일 바로 위 두 단계(`{그룹번호}/cropped`)만 본다
2. 시작 시 `mapping/storage_ab_defect_info.csv`가 기본으로 로드됨 (다른 매핑 CSV로 교체 가능)
3. 확장자 선택 후 "목록 불러오기" — 그룹번호와 crop 순서로 셀 인덱스를 계산해 매핑표에서 올바른 A열 저장번호를 조회하고, 그 값으로 재명명한 결과를 미리보기로 보여줌. 그룹번호를 못 찾거나(`cropped` 폴더 바로 위가 숫자가 아님), image_cropper 형식이 아니거나, 계산된 셀 인덱스가 매핑표에 없으면 "매칭실패"
4. 이후 흐름은 탭 1/탭 2와 동일

## 파일명 매칭 규칙 (탭 1)

파일명 규칙이 시기별로 달라, 두 방식을 모두 시도한다 (구형 패턴이 없으면 신형 패턴을 시도):

1. **구형**: 원본 파일명에서 정규식 `\d{4}-\d{2}-\d{2}-(\d+)-` (예: `2025-01-16-7780-...`)로 바코드를 직접 추출
2. **신형**: 원본 파일명에서 정규식 `Test#[AB]\d+-\d+` (예: `Test#A8-0000008`)로 저장번호를 추출한 뒤, `storage_cellbarcode_map.csv`에서 Cell Barcode(예: `Test_2025_01_16_7632`)를 조회하고, 그 마지막 `_` 이후 숫자를 바코드로 사용

이후 공통 단계:
- `barcode_cell_map.csv`에서 바코드 → 셀번호 조회
- `cell_material_map.csv`에서 셀번호 → 재료명 조회
- 최종 파일명: `{재료명}_{셀번호}_{원본파일명}`
- 어느 단계든 실패하면 "매칭실패" 상태 + 구체적 사유(바코드/저장번호 패턴 없음 / 저장번호가 매핑표에 없음 / 바코드가 매핑표에 없음 / 셀번호가 매핑표에 없음)로 표시되고, 정상 변환 대상에서는 제외되지만 "모두 변환" 시 error 폴더로는 복사됨

## Crop 재명명 규칙 (탭 2)

- image_cropper 출력 파일명 규칙: `{원본파일명}_{ROI번호}_x{x}y{y}w{w}h{h}{확장자}` (image_cropper 의 규칙과 동일, `utils/image_cropper/processing.md` 참고)
- 원본파일명 안의 저장번호(`Test#A4-0000004` 형식)에서 시리얼 번호를 crop별로 다음과 같이 조정 (같은 4개 시리얼을 방향만 반대로 배정):
  - **내림차순(기본, 미체크)**: crop 1은 그대로, crop 2/3/4는 시리얼을 각각 1/2/3 감소. 예) `Test#A4-0000004` → crop 1~4는 각각 `Test#A4-0000004`/`Test#A3-0000003`/`Test#A2-0000002`/`Test#A1-0000001`
  - **오름차순(체크 시)**: crop 4는 그대로(원본 시리얼), crop 1/2/3은 시리얼을 각각 3/2/1 감소. 예) `Test#A4-0000004` → crop 1~4는 각각 `Test#A1-0000001`/`Test#A2-0000002`/`Test#A3-0000003`/`Test#A4-0000004`
- lane 번호(A/B 뒤의 숫자)는 `storage_cellbarcode_map.csv`와 동일한 1~8 순환 규칙(`((시리얼-1) % 8) + 1`)으로 새로 계산 (단순히 base 파일의 lane을 그대로 감소시키지 않음)
- 재명명 결과 = crop 접미사(`_{ROI번호}_x..y..w..h..`)를 제거하고 저장번호만 교체한 파일명

## 그룹폴더 기반 Crop 재명명 규칙 (`gui_folder_remap.py`)

탭 2와 달리 **베이스 파일명에 박힌 저장번호는 신뢰하지 않는다** (GitHub 이슈 #5: 실제 셀 위치와 어긋나는 사례 발견). 대신:

- 폴더 구조 `{그룹번호}/cropped/{crop파일}`에서 그룹번호 N을 읽음 (`folder_crop_remap.extract_group_number`). 폴더명 앞자리 숫자만 읽으므로 `"02"`(0 무시) → 2, `"35 (스크랩無)"`(뒤 텍스트 무시) → 35 처럼 처리됨
- 그룹 N은 셀 인덱스 `[4N-3, 4N-2, 4N-1, 4N]` 4개를 담고, cropped 폴더의 crop 1~4가 **오름차순**으로 이 4개에 배정됨(crop1→4N-3 … crop4→4N) — 탭 2의 "오름차순" 옵션과 동일한 방향, 항상 이 방향만 사용(옵션 없음)
- 계산된 셀 인덱스로 `storage_ab_defect_info.csv`의 `No` 컬럼을 조회해 올바른 `A열_저장번호`를 가져옴
- crop 접미사를 제거한 베이스 파일명 안에서 (틀렸을 수 있는) 기존 `Test#[AB]..` 패턴을 찾아 그 값으로 치환 (패턴이 아예 없으면 앞에 붙임) — 나머지 파일명(날짜/타임스탬프 등)은 그대로 유지됨

## 비동기 처리 (GUI 응답성)

폴더 스캔(`ScanWorker`)과 파일 변환(`ConvertWorker`)은 모두 `QThread`로 메인 스레드 밖에서 실행된다 (두 탭 공용). 변환 중에는 `progress_cb(done, total)` 콜백으로 진행 상황이 `QProgressBar`와 상태바에 실시간 반영되며, 스캔/변환 중에는 폴더·매핑·출력 재선택, 중복검사, 되돌리기 등 충돌 가능한 조작 버튼이 잠긴다 (`ConversionTab._set_busy`, 탭별 추가 버튼은 `_extra_lock_widgets`로 함께 잠김). 대량 파일(수천 건) 변환처럼 오래 걸리는 작업에도 창이 멈추지 않는다.

## 한글(유니코드) 파일명 지원

- 매핑 CSV는 `utf-8-sig`로 읽고 쓴다 (Excel에서 열어도 한글이 깨지지 않도록 BOM 포함).
- 변환 로그(`_conversion_log_*.json`)는 `ensure_ascii=False`로 저장해 한글이 유니코드 이스케이프가 아닌 실제 문자로 저장된다.
- Windows 콘솔(cp949)에서 한글 출력이 깨지는 것을 막기 위해 `gui.py`(및 레거시 두 스크립트, 테스트 데이터 생성 스크립트)는 시작 시 `sys.stdout`/`stderr`를 UTF-8로 강제 재설정한다.
- 파일 시스템 경로 자체는 Python 3 + Windows 환경에서 기본적으로 유니코드를 지원하므로 별도 처리가 필요 없다.

## 제약 사항

- 변환은 항상 **복사**만 수행한다 (원본 파일을 이동하거나 이름을 바꾸지 않음). 원본 폴더의 파일명은 절대 바뀌지 않는다.
- "평탄화" 모드에서 동일 최종명이 여러 개 있으면 변환 자체가 차단된다 — 중복검사로 어느 파일이 겹치는지 확인하고 체크를 해제해야 진행 가능하다.
- "되돌리기"는 반드시 이 도구가 만든 변환 로그(json)를 기준으로만 동작한다. 로그 파일을 지우거나 출력 폴더를 옮기면 되돌릴 수 없다(원본은 애초에 건드리지 않으므로 데이터 손실 위험은 없음).
- `barcode_to_cellNum.py`/`cellNum_to_barcode.py`는 레거시 스크립트로, 하드코딩된 경로(`D:\...`)와 매핑을 그대로 갖고 있어 이 저장소 밖 환경을 가정한다. 새 작업은 `gui.py`를 사용할 것.
- Crop 재명명(탭 2)은 image_cropper의 출력 파일명 규칙(`_{ROI번호}_x..y..w..h..`)에 정확히 의존한다. 다른 방식으로 자른 이미지는 매칭실패로 처리됨.
- Crop 재명명은 파일명만 재구성할 뿐 매핑표 조회를 하지 않으므로, 재명명된 시리얼/lane이 실제로 barcode_cell_map.csv 등에 존재하는지는 탭 1에서 다시 불러와야 확인할 수 있다.
