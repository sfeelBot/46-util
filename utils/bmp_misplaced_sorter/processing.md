# bmp_misplaced_sorter — processing.md

- 경로: `utils/bmp_misplaced_sorter/`
  - `sort_misplaced.py`: 실행 진입점 (GUI 없음)
  - `storage_number_map.csv`: GitHub 이슈 #6의 매칭표를 그대로 파싱해 저장한 CSV (152행, 컬럼: 순번/제품유형/값/CellBarcode/저장번호/실제저장번호)
- 목적: 상위폴더 안의 `Test#A[1-8]-0000NNN` 형식 폴더들에 데이터가 꼬여 잘못 들어간 bmp 파일을 매칭표 기준으로 찾아내어, 상위폴더의 `error/`(원본 백업)와 `rename/<진짜 소속 폴더명>/`(정리된 사본)으로 재배치한다.
- 배경(이슈 #6): 152개 폴더 중 대부분은 "폴더명 = 그 폴더에 있어야 할 파일명 접두사"가 같지만, 24개 폴더(csv 순번 9~16, 49~56, 105~112)는 실제 촬영 시 번호가 밀려서 "실제저장번호"가 폴더명과 다르게 별도로 지정되어 있다. 예: 순번13 폴더 `Test#A5-0000013`의 정상 파일 접두사는 폴더명이 아니라 `Test#A5-0000021-14`.
- 의존성: 없음 (표준 라이브러리 `os`, `csv`, `shutil`, `sys`만 사용)
- 버전: v1 (2026-07-13)
- 사용법:
  ```
  cd "E:\46 util"
  .venv\Scripts\python.exe utils\bmp_misplaced_sorter\sort_misplaced.py "D:\path\to\top_folder"
  ```
  - 인자 없이 실행하면 `input()`으로 경로를 물어봄.
  - `storage_number_map.csv`는 스크립트와 같은 폴더에서 자동으로 로드됨 (별도 인자 불필요).
  - 처리 후 콘솔에 처리폴더수/정상/재배치/미인식 건수 요약 print.
  - 상위폴더에 `sort_log.csv`(utf-8-sig, 컬럼: 원래폴더/원본파일명/상태/실제소속폴더/결과파일명) 저장. 상태값: `relocated`(재배치 성공) / `unrecognized`(어떤 접두사와도 안 맞음) / `error_conflict`(진짜 소속 폴더는 찾았지만 rename 대상 경로에 이미 파일 존재).
- 알고리즘:
  - CSV에서 `저장번호 → 기대접두사`(실제저장번호가 있으면 그 값, 없으면 저장번호 자신) 매핑을 만들고, 역방향 조회용으로 접두사 문자열이 긴 것부터 정렬한 리스트도 만든다.
  - 상위폴더 바로 아래 하위폴더 중 CSV의 "저장번호"와 이름이 일치하는 폴더만 처리 대상으로 삼는다 (표에 없는 폴더명은 완전히 건드리지 않음).
  - 각 대상 폴더 안의 bmp 파일을 재귀 탐색(`os.walk`)하여, 파일명이 자기 폴더의 기대접두사로 시작하지 않으면 "잘못 들어간 파일"로 판정한다.
  - 잘못 들어간 파일: 원본을 `error/`로 이동(이름 충돌 시 `_dupN` 접미사) → 역방향 조회로 진짜 소속 폴더를 찾아 `rename/<진짜소속폴더>/`에 접두사를 그 폴더명으로 치환한 이름으로 복사(대상 경로에 이미 파일이 있으면 복사 생략, `error_conflict`로 로그).
  - 아무 접두사와도 안 맞는 파일은 `error/`에만 남기고 `rename/`에는 넣지 않음(`unrecognized`).
- Edge case 처리:
  - 상위폴더가 없으면 에러 메시지 출력 후 exit code 1
  - CSV에 없는 폴더(예: `error/`, `rename/` 자기 자신, 또는 목록에 없는 이름)는 스캔 대상에서 자동 제외
  - `.bmp`가 아닌 파일은 건드리지 않음
- 상태: 완료 (서브에이전트 검증 통과, 2026-07-13)
- 비고:
  - `storage_number_map.csv`는 GitHub 이슈 #6 표를 API로 그대로 가져와 파싱한 것이므로, 표 내용이 갱신되면 이 CSV도 다시 받아 갱신해야 함.
  - 원본 파일은 error/로 **이동**(move)되므로 원본이 사라진다. 실행 전 백업 권장.
  - 재실행해도 안전(idempotent): 이미 옮겨진 파일은 원래 폴더에 없으므로 중복 처리되지 않음.
