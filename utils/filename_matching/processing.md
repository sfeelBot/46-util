# filename_matching — processing.md

## 목적

이물검사 이미지 파일명을 "바코드 → 셀번호 → 재료명" 순으로 재가공하는 도구.
원래는 `barcode_to_cellNum.py`(바코드→셀번호) → `cellNum_to_barcode.py`(셀번호→재료명) 두 단계를 순서대로 따로 실행해야 했는데, 이 두 단계를 하나의 파이프라인으로 묶고 GUI로 미리보기/중복검사/일괄 변환/되돌리기까지 할 수 있게 만들었다.

## 구성 파일

| 파일 | 역할 |
|------|------|
| `gui.py` | PyQt5 GUI 메인 (실행 진입점) |
| `core.py` | GUI 비의존 핵심 로직 (스캔/매핑/변환명 계산/중복검사/변환/되돌리기) — 단위 테스트·서브에이전트 검증 대상 |
| `mapping/barcode_cell_map.csv` | 바코드 ↔ 셀번호 매핑 (컬럼: `barcode,cell`) |
| `mapping/cell_material_map.csv` | 셀번호 ↔ 재료명 매핑 (컬럼: `cell,material`) |
| `barcode_to_cellNum.py` | (레거시, 독립 실행용) 바코드→셀번호 1단계만 수행하던 원본 스크립트. 하드코딩된 경로/매핑 사용 |
| `cellNum_to_barcode.py` | (레거시, 독립 실행용) 셀번호→재료명 2단계만 수행하던 원본 스크립트. 하드코딩된 경로/매핑 사용 |
| `test_data/_generate_test_data.py` | GUI/core 검증용 예제 파일(한글 파일명 포함) 생성 스크립트 |
| `_generate_default_mapping.py` | 레거시 두 스크립트의 하드코딩 매핑을 `mapping/*.csv` 기본값으로 변환한 1회성 스크립트 (재실행 시 CSV를 원래 하드코딩 값으로 되돌림) |

## 사용법

```
.venv\Scripts\python.exe utils/filename_matching/gui.py
```

1. **매핑 파일 확인/교체** — 시작 시 `mapping/barcode_cell_map.csv`, `mapping/cell_material_map.csv`가 기본으로 로드됨. 다른 매핑표를 쓰려면 각 "매핑 불러오기..." 버튼으로 다른 CSV를 선택 (코드 수정 없이 교체 가능)
2. **폴더 선택** — 대상 폴더 선택 시 하위 폴더까지 재귀적으로 스캔해 존재하는 확장자 목록을 체크박스로 보여줌
3. **확장자 선택 후 "목록 불러오기"** — 선택한 확장자만 대상으로 목록을 만들고, 각 파일의 최종 변환명(`{재료명}_{셀번호}_{원본파일명}`)을 미리보기로 계산. 바코드 패턴이 없거나 매핑표에 없는 파일은 "매칭실패" + 사유로 표시되고 자동으로 체크 해제됨
4. **중복검사** — 현재 선택된 출력 모드(평탄화/구조유지) 기준으로 최종 변환명이 겹치는 항목을 찾아 빨간색으로 표시
5. **목록 우클릭 → "파일탐색기에서 열기"** — 원본 파일 위치를 탐색기로 바로 열어줌
6. **출력 폴더 선택 + 출력 모드 선택**
   - 단일 폴더에 평탄화: 하위폴더 구분 없이 출력 폴더 하나에 모든 결과 파일을 모음
   - 원본 하위폴더 구조 유지: 출력 폴더 아래에 원본과 동일한 하위폴더 구조를 그대로 재현
7. **모두 변환** — 체크되고 매칭에 성공한 파일만 원본을 그대로 둔 채(복사) 출력 폴더로 복사. 실행 직전 목적지 경로 충돌(같은 이름 중복, 또는 출력 폴더에 이미 같은 이름 존재)을 재검사해서, 충돌이 있으면 아무 파일도 복사하지 않고 팝업으로 충돌 목록을 보여줌
8. **되돌리기**
   - "되돌리기 (방금 실행)": 직전 변환에서 생성된 결과 파일만 삭제 (원본은 항상 그대로)
   - "로그 불러와서 되돌리기...": 앱을 재시작했어도, 출력 폴더에 남은 `_conversion_log_YYYYMMDD_HHMMSS.json`을 선택하면 해당 실행분만 되돌릴 수 있음

## 파일명 매칭 규칙

- 원본 파일명에서 정규식 `\d{4}-\d{2}-\d{2}-(\d+)-` (예: `2025-01-16-7780-...`)로 바코드를 추출
- `barcode_cell_map.csv`에서 바코드 → 셀번호 조회
- `cell_material_map.csv`에서 셀번호 → 재료명 조회
- 최종 파일명: `{재료명}_{셀번호}_{원본파일명}`
- 위 세 단계 중 하나라도 실패하면 "매칭실패" 상태 + 구체적 사유(패턴 없음 / 바코드가 매핑표에 없음 / 셀번호가 매핑표에 없음)로 표시되고 변환 대상에서 제외됨

## 비동기 처리 (GUI 응답성)

폴더 스캔(`ScanWorker`)과 파일 변환(`ConvertWorker`)은 모두 `QThread`로 메인 스레드 밖에서 실행된다. 변환 중에는 `progress_cb(done, total)` 콜백으로 진행 상황이 `QProgressBar`와 상태바에 실시간 반영되며, 스캔/변환 중에는 폴더·매핑·출력 재선택, 중복검사, 되돌리기 등 충돌 가능한 조작 버튼이 잠긴다 (`MainWindow._set_busy`). 대량 파일(수천 건) 변환처럼 오래 걸리는 작업에도 창이 멈추지 않는다.

## 한글(유니코드) 파일명 지원

- 매핑 CSV는 `utf-8-sig`로 읽고 쓴다 (Excel에서 열어도 한글이 깨지지 않도록 BOM 포함).
- 변환 로그(`_conversion_log_*.json`)는 `ensure_ascii=False`로 저장해 한글이 유니코드 이스케이프가 아닌 실제 문자로 저장된다.
- Windows 콘솔(cp949)에서 한글 출력이 깨지는 것을 막기 위해 `gui.py`(및 레거시 두 스크립트, 테스트 데이터 생성 스크립트)는 시작 시 `sys.stdout`/`stderr`를 UTF-8로 강제 재설정한다.
- 파일 시스템 경로 자체는 Python 3 + Windows 환경에서 기본적으로 유니코드를 지원하므로 별도 처리가 필요 없다.

## 제약 사항

- 변환은 항상 **복사**만 수행한다 (원본 파일을 이동하거나 이름을 바꾸지 않음). 원본 폴더의 파일명은 절대 바뀌지 않는다.
- "평탄화" 모드에서 동일 최종명이 여러 개 있으면 변환 자체가 차단된다 — 중복검사로 어느 파일이 겹치는지 확인하고 체크를 해제해야 진행 가능하다.
- "되돌리기"는 반드시 이 도구가 만든 변환 로그(json)를 기준으로만 동작한다. 로그 파일을 지우거나 출력 폴더를 옮기면 되돌릴 수 없다(원본은 애초에 건드리지 않으므로 데이터 손실 위험은 없음).
- `barcode_to_cellNum.py`/`cellNum_to_barcode.py`는 레거시 스크립트로, 하드코딩된 경로(`D:\...`)와 매핑을 그대로 갖고 있어 이 저장소 밖 환경을 가정한다. 새 작업은 `gui.py`를 사용할 것.
